# Канон — замеры, силовые, питание и 3D-модель тела

Личное PWA-приложение: вводите замеры, импортируете тренировки из Hevy и видите 3D-модель своего тела, пропорции, уровень прокачки и советы со ссылками на исследования. Всё бесплатно, без сервера и аккаунтов: данные хранятся **только на телефоне**.

| Раздел | Что внутри |
|---|---|
| Первый запуск | Мастер настройки под любого человека: пол, возраст, рост, вес, цель, стаж, активность, ограничения по здоровью |
| Главная | Уровень (9 ступеней от «Старт» до «Греческий бог» / «Греческая богиня»), 3D-модель (сейчас / **прогноз через N месяцев и натуральный потолок** / цель / Ривз / дата A против B, тепловая карта, мужская и женская; мышечный рельеф растёт с FFMI), ключевые показатели, сильные и отстающие зоны, сравнение недель |
| Замеры | 17 полей по группам, у каждого режим «😌 не напрягать / 💪 напрячь / 🦴 кость» и подсказка «как мерить» (включая трицепс в напряжении), графики, сравнение дат, импорт CSV из любого приложения или умных весов, фото прогресса с контуром и ползунком «было/стало» |
| Силовые | Импорт CSV из любого приложения (Hevy, Strong, FitNotes, своя таблица) с автосопоставлением колонок, превью и защитой от дублей; ключевые движения по 6 паттернам — штанга, гантели, Смит и тренажёры; ~90 правил распознавания упражнений (рус./англ.) с ручной правкой мышц, типа движения, оборудования и рисков; подходы на мышцу, тоннаж, рекорды, 1ПМ; предупреждения по 10 ограничениям здоровья |
| Питание | BMR / TDEE (калькулятор активности по шагам, тренировкам и работе стоя; адаптивный по факту), цели КБЖУ, дневник, шаблоны, «повторить день», импорт CSV (MyFitnessPal, Cronometer, своя таблица), поиск в Open Food Facts, автооценка клетчатки и сахара («≈»), ₽ и белок на 100 ₽, прогноз даты цели |
| Советы | **Мини-отчёт «что качать»**: приоритет зон для эстетики, слабые движения, объём, питание, прогноз на 6/12 мес. и потолок; правила по вашим данным со ссылками на PubMed/DOI; эвристики отдельно; «Скопировать контекст для ИИ» |
| Настройки | Профиль, активность, цели, 10 ограничений по здоровью, тема, бэкап/восстановление, CSV, напоминания в календарь, повторная настройка профиля |

## 1. Запуск на компьютере (Windows, PowerShell)

Нужен Node.js 22.12 или новее (у вас стоит Node 26 — подходит).

```powershell
cd C:\ClaudeBase\projects\body-tracker
```
Переходим в папку проекта.

```powershell
npm install
```
Скачивает библиотеки из `package.json` в папку `node_modules` (≈ 200 МБ, один раз).

```powershell
npm run dev
```
Запускает сервер разработки. Откройте в браузере адрес из консоли (http://127.0.0.1:5173). Изменения в коде видны сразу. Остановить — `Ctrl + C`.

```powershell
npm run check
```
Полная проверка: типы TypeScript → 164 юнит-теста → сборка. Если где-то ошибка, команда остановится и покажет её.

```powershell
npm run build
npm run preview
```
Собирает готовую версию в папку `dist` и показывает её на http://127.0.0.1:4173 — так же, как она будет работать в интернете (с офлайн-режимом).

Другие команды:

| Команда | Что делает |
|---|---|
| `npm test` | Только юнит-тесты (формулы, импорт из разных приложений, распознавание упражнений, бэкап, 3D-калибровка) |
| `npm run typecheck` | Только проверка типов |
| `npm run model` | Пересобрать 3D-модель из исходников MakeHuman (`model-src/`) |
| `npm run icons` | Пересоздать иконки приложения |
| `npm run verify-sources` | Перепроверить все PMID/DOI через PubMed и Crossref (нужен интернет) |
| `& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python scripts/blender/make_blend.py` | Пересоздать `model-src/body.blend` (30 shape keys) из несжатого GLB. `&` нужен PowerShell, чтобы запустить программу из пути с пробелами |

## 2. Бесплатный деплой (GitHub Pages)

Почему GitHub Pages: бесплатно, без карты, HTTPS (обязателен для PWA). 09.11.2026 `pages.github.com` открывался с этого ноутбука (HTTP 200). **Не проверено** с мобильного интернета в России без VPN — проверьте сами после деплоя. Если сайт не откроется: установленное приложение всё равно работает офлайн, интернет нужен только для обновлений; запасные варианты — в разделе «Ограничения».

Регистрацию и вход делаете **вы сами** — я аккаунты не создаю.

1. Зарегистрируйтесь на https://github.com (бесплатный план). Подтвердите почту.
2. Создайте репозиторий: кнопка «+» → **New repository** → имя `kanon` → **Public** (Pages бесплатны для публичных; данные приложения в репозиторий не попадают — они живут только в телефоне) → **Create repository**.
3. Один раз настройте имя и почту для Git (подставьте свои):

```powershell
git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта"
```
Git подписывает этими данными коммиты.

4. Отправьте код (в папке проекта; `ЛОГИН` — ваш логин GitHub):

```powershell
cd C:\ClaudeBase\projects\body-tracker
git add .
git commit -m "Канон: первая версия"
git remote add origin https://github.com/ЛОГИН/kanon.git
git push -u origin main
```
`git add .` — добавить все файлы (кроме `node_modules` и `dist`, они в `.gitignore`); `git commit` — сохранить снимок; `git remote add` — указать адрес репозитория; `git push` — отправить. При первом `push` откроется окно входа в GitHub — войдите в браузере.

5. На GitHub: репозиторий → **Settings** → **Pages** → в «Build and deployment» выберите **Source: GitHub Actions**.
6. Вкладка **Actions** → дождитесь зелёной галочки у «Deploy to GitHub Pages» (2–3 минуты). Workflow сам прогоняет типы, тесты и сборку — если тест упадёт, сайт не обновится.
7. Сайт: `https://ЛОГИН.github.io/kanon/`.

> Workflow `.github/workflows/deploy.yml` написан, но **ещё ни разу не запускался** (нет аккаунта). Если первый запуск упадёт — пришлите текст ошибки из вкладки Actions.

## 4. Установка на iPhone

1. Откройте `https://ЛОГИН.github.io/kanon/` **в Safari** (не в Chrome — на iOS ставить на экран «Домой» умеет только Safari).
2. Кнопка «Поделиться» (квадрат со стрелкой) → **На экран «Домой»** → **Добавить**.
3. Запускайте с иконки «Канон»: полноэкранный режим, работает без интернета.
4. Сразу сделайте первый бэкап: Настройки → «Сохранить бэкап» → «Сохранить в Файлы» → iCloud Drive.

**Важно про данные на iOS.** Safari может удалить данные сайта, который *не установлен* на экран «Домой» и не открывался около 7 дней. Установленное приложение защищено лучше, а приложение дополнительно просит у браузера «постоянное хранилище» (`navigator.storage.persist()`). Но если удалить иконку — данные удалятся вместе с ней. Поэтому: **бэкап раз в неделю** (приложение напоминает баннером) и напоминания в календаре (Настройки → «Скачать напоминания (.ics)»).

## 5. Как это устроено

| Слой | Решение |
|---|---|
| Интерфейс | Vite 8 + React 19 + TypeScript 7, без UI-библиотек, навигация через `#hash` (работает в подпапке GitHub Pages) |
| Данные | IndexedDB через Dexie 4; таблицы: замеры, подходы, еда, шаблоны, фото, правки упражнений, настройки |
| Офлайн | vite-plugin-pwa (Workbox): всё приложение и 3D-модель в кэше; обновление по кнопке |
| 3D | three.js + React Three Fiber + Drei, `frameloop="demand"`, DPR ≤ 2, отдельный ленивый чанк |
| Модель | MakeHuman (CC0) → свой скрипт `scripts/build-model.ts` → GLB с 30 morph targets, сжатие meshopt (2,5 МБ → 0,75 МБ) |
| Расчёты | Чистые функции в `src/lib/calc`, `src/lib/hevy`, `src/lib/model`, `src/lib/advice` — покрыты тестами |

### Калибровка 3D-модели
1. Для каждого замера на меше есть сечение у анатомической точки (шея — у кадыка, талия — на уровне пупка, бицепс — середина плеча и т. д.). Плоскость сечения привязана к суставам MakeHuman, поэтому двигается вместе с морфами.
2. «Обхват лентой» модели = периметр **выпуклой оболочки** сечения (лента не заходит во впадины).
3. Рост — бисекцией по морфу роста. Мышечность и жир задаются из нормализованного FFMI и % жира (эвристика).
4. Каждый обхват подгоняется своим морфом бисекцией; 4 круга координатного спуска, потому что морфы влияют друг на друга.
5. Отклонение каждого замера показывается под моделью; > 2 см — помечается «вне допуска», выход за родной диапазон MakeHuman — «экстраполяция».

### Формулы (подробно с источниками — `SOURCES.md`)

| Что | Формула |
|---|---|
| % жира (ВМС США), муж. | 495 / (1.0324 − 0.19077·log10(талия − шея) + 0.15456·log10(рост)) − 450 |
| % жира, жен. | 495 / (1.29579 − 0.35004·log10(талия + таз − шея) + 0.22100·log10(рост)) − 450 |
| LBM, FFMI | LBM = вес·(1 − BF/100); FFMI = LBM/рост_м²; норм. FFMI = FFMI + 6.1·(1.8 − рост_м) |
| 1ПМ | среднее Epley w·(1 + r/30) и Brzycki w·36/(37 − r), только r ≤ 10 |
| DOTS | сумма·500 / (a + b·bw + c·bw² + d·bw³ + e·bw⁴) |
| BMR | Mifflin–St Jeor; если известна LBM — Katch–McArdle 370 + 21.6·LBM |
| Адаптивный TDEE | средние ккал − наклон веса (кг/день)·7700, окно 21 день |
| Тренд веса | EMA с учётом пропусков: α = 1 − e^(−Δt/7) |

### Импорт из любого приложения (`src/lib/import/`)
Официальных спецификаций экспорта у Strong, FitNotes, MyFitnessPal и Cronometer нет, поэтому импорт не угадывает форматы, а работает так:
1. Разделитель (`,` `;` TAB) и формат дат определяются автоматически.
2. Колонки сопоставляются по словарю синонимов на английском и русском (`exercise name`, «упражнение», `weight (kgs)`, «вес, кг», `fatRate`, `Energy (kJ)`…).
3. В превью видно сопоставление и пример строки — любую колонку можно переназначить вручную.
4. Повторный импорт не создаёт дублей (тренировки — по времени, упражнению и номеру подхода; еда — по дате, названию, ккал и белку; замеры — дополняют пустые поля дня).

### Прогноз и мышечный рельеф (`src/lib/calc/forecast.ts`)
- Два стиля цели: **«Эстетика»** (по умолчанию; сухое атлетичное тело: FFMI ≈ 23 / жен. 19,5, жир ≈ 10 % / жен. 19 %, верх растёт быстрее, ноги и шея умеренно, плечи тянутся к 1,6 × талия) и **«Максимум массы»** (натуральный потолок). Режим 3D «Цель» показывает эстетический итог; мини-отчёт берёт цели оттуда же.
- Сухая масса растёт экспоненциально к потолку: в начале со скоростью для вашего стажа (стаж 4+ лет ≈ 1,75 кг/год, у женщин вдвое меньше), у потолка — к нулю. Потолок — Casey Butt (если есть запястье и лодыжка) или нормализованный FFMI 25 / 21.
- Жир идёт к целевому % темпом сушки. Мышечные обхваты ∝ √(сухая масса) и тянутся к потенциалу Butt; талия уменьшается ≈ на 0,9 см на кг жира.
- На 3D это задаёт общий морф мышечности и морф «рельеф» (грудные, широчайшие, дельты, руки, ноги из CC0-таргетов MakeHuman), силу которых определяют FFMI и % жира. Обхваты затем подгоняются под прогноз.
- Это модель-эвристика: реальная скорость у тренированных очень индивидуальна.

### Активность (`src/lib/calc/activity.ts`)
TDEE = BMR × 1,2 (сидячий базис) + ходьба сверх 4000 шагов + тренировки + работа стоя. Чистый расход = (MET − 1) × кг × часы, MET из Compendium of Physical Activities (ходьба 3,5; силовая 3,5 или 6; работа стоя 2,0 против 1,3 сидя). Пример: 80 кг, 17 000 шагов, 3–4 тренировки, 20 ч на ногах → ≈ ×1,58 от BMR. Через 2–3 недели данных приложение переходит на адаптивный TDEE по фактическому весу и дневнику.

### Уровни (`src/lib/calc/levels.config.ts`)

| Компонент | Вес | 0 баллов → 100 баллов | Почему такой вес |
|---|---|---|---|
| Нормализованный FFMI | 30 % | 18 → 25 | Главный показатель мышц с поправкой на рост; 25 — ориентир натурального потолка (Kouri 1995) |
| % жира | 20 % | 25 % → 10 % (ниже 6 % балл снижается) | Рельеф и здоровье; экстремальная сухость не поощряется |
| Относительная сила | 20 % | лучшее упражнение в каждом из 6 паттернов (жимы, присед/жим ногами, наклон, тяги); у штанги, гантелей, Смита и тренажёров свои ориентиры, например жим штанги 0.75→1.75×, жим в тренажёре 0.7→1.7×, жим ногами 1.5→4.0× веса | Учитывает и тренажёрные программы |
| Плечи / талия | 15 % | 1.2 → 1.618 | V-силуэт, эстетический ориентир |
| Пропорции Ривза | 15 % | 75 % → 100 % | Гармония, но это эвристика 1950-х — вес ниже |

Для женщин своя шкала (эвристика): FFMI 14→21, жир 35 %→18 %, плечи/талия 1.1→1.45, силовые ориентиры ×0,6 (верх) и ×0,7 (низ), Ривз не применяется; вершина — «Греческая богиня» (FFMI ≥ 20.5, жир 16–22 %).

Помимо балла у верхних уровней есть **обязательные условия**: «Греческий бог» — нормализованный FFMI ≥ 24.5, жир 8–11 %, плечи/талия ≥ 1.6, Ривз ≥ 95 %, силовой балл ≥ 90. Высокий балл без них уровень не даёт. Сроки «до следующего уровня» — грубая оценка: 1–2.5 кг сухой массы в год при стаже 4+ лет (эвристика, высокая неопределённость), сушка 0.5–1 % массы в неделю (Helms 2014, Garthe 2011).
